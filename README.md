**gemini-to-dsh** — мост, который заводит Gemini в [DSH](https://github.com/deepseek-ai/deepseek-harness) и в любой другой клиент, говорящий на OpenAI. В комплекте: слой выхода в сеть для случаев, когда Гугл напрямую недоступен, веб-поиск с настоящим кэшем и панель с квотой и переключением режимов.

Без зависимостей. Node 20+. Два локальных порта.

```text
DSH / любой OpenAI-клиент
        │  POST /v1/chat/completions   (SSE)
        ▼
127.0.0.1:8787  мост ── переводит OpenAI ↔ Cloud Code, крутит аккаунты
        │  CONNECT-туннель
        ▼
127.0.0.1:8789  шим выхода ── выбирает канал, сохраняет SNI
        │
        ▼
smart-DNS ──► Google Cloud Code ──► Gemini
```

## Что внутри

| | |
| --- | --- |
| **Полная поверхность OpenAI** | Стриминг и обычные ответы, инструменты с `tool_choice`, изображения, `reasoning_content`, usage с числом закэшированных токенов |
| **Несколько аккаунтов** | Запросы идут по остатку пятичасового окна; переключение случается до `429`, а не после |
| **Слой выхода** | Каналы `DNS` / `Proxy` / `VPN` / `Direct`, сторож проверяет канал настоящим ответом |
| **Панель в DSH** | Квота на два окна и управление выходом одной кнопкой |
| **Веб-поиск** | API с ключами → DuckDuckGo, кэш, пейсинг, кулдаун |
| **Картинки** | «Нарисуй кота» уходит в модель-художник сама |

## Быстрый старт

### Одной командой

```bash
git clone https://github.com/ext3ndedsoft/gemini-to-dsh.git
cd gemini-to-dsh
node install.mjs
```

Ставит мост в `~/.dsh/bridge`, панель квоты в профиль DSH и дописывает её в `cordis.patch.yml` — не трогая то, что там уже есть. Повторный запуск ничего не дублирует. Дальше остаются только креды. По шагам, если хочется руками: [docs/plugin-install.md](docs/plugin-install.md).

### Аккаунты

Мост переиспользует OAuth-токены, которые подписка Google AI Pro уже создала на машине (это доступ Cloud Code, а не ключ с бесплатного тарифа). Положи их туда, где мост их ждёт — `~/.gemini/oauth_creds.json` для первого аккаунта и `~/.gemini/dsh-bridge/accounts.json` для набора ротации — либо укажи другие пути через `AG_CREDS_FILE` / `AG_ACCOUNTS_FILE`. OAuth-клиент, которым эти токены обновляются, **в репозиторий не входит**: задай `AG_CLIENT_ID` и `AG_CLIENT_SECRET` или положи их в `~/.dsh/ag-oauth.json`.

```bash
cd bridge && node bridge.js
curl -s localhost:8787/limits -H 'authorization: Bearer local-bridge' | head
```

### Если Гугл доступен напрямую

```bash
AG_EGRESS=0 ./start.sh          # macOS / Linux
# или: set "AG_EGRESS=0" && bridge\start.cmd     (Windows)
```

`AG_EGRESS=0` вообще не поднимает шим — ни лишнего хопа, ни настройки каналов.

### Если нет

Запускай без этой переменной. Цепочка по умолчанию (`bezmezhau → geohideeu → geohide → magicdns → direct`) зашита в дефолты, так что первый запуск работает как есть; каналы со временем умирают — для этого и нужен сторож. Свой канал добавляется из панели (`свой DNS`) или из терминала:

```bash
cd bridge
node egress-ctl.mjs add mydns 203.0.113.10 203.0.113.11 --seeds=cloudaicompanion.googleapis.com
node egress-ctl.mjs use mydns
node egress-ctl.mjs check mydns
```

### Подключение к DSH

Провайдер смотрит на локальный порт. Минимальный патч профиля:

```yaml
# ~/.dsh/profiles/web/cordis.patch.yml
- id: agent-default-model
  config:
    provider: antigravity
    model: gemini-3.8-flash
    reasoningEffort: medium
```

Мост принимает любой `Authorization`, совпадающий с `AG_BRIDGE_SECRET` (по умолчанию `local-bridge`), поэтому в записи провайдера нужен именно такой bearer.

## Панель

<p align="center">

  &nbsp;
  <img src="assets/panel-proxy.png?v=2" alt="Панель: режим Proxy, адрес и проверка тоннеля" width="384">
</p>

Панель управляет, а не только показывает. Режим выхода переключается прямо в ней, и под каждым режимом раскрывается то, что ему нужно: в `DNS` — чип на каждый канал, «наша цепочка» и поле для своего резолвера; в `Proxy` — адрес (ссылкой, с логином или просто `host:port`), запасной адрес и кнопка «проверить», которая открывает туннель и **ничего не сохраняет**. Каждое нажатие — один `POST` в шим; панель не держит своё состояние, а рисует то, что ответил шим.

По каждому аккаунту видны обе гугловые квоты: пятичасовая и **недельная** — кольцом с процентом и таймером до сброса, отдельно по группам («Gemini Models», «Claude and GPT models»).

## Как это работает

**Стриминг, похожий на печать, а не на загрузку.** Гугл отдаёт ~25 токенов раз в ~300 мс; если пропускать как есть, текст падает лепёшками. Мост режет каждую порцию на мелкие дельты с ровным тактом (`30 мс`, `AG_PACE_MS`). Размышления уходят сразу, а не задерживаются до конца хода.

**Честные ошибки.** Отклонённый запрос возвращается один раз, а не долбится трижды в ту же стену — повтор осмыслен только для `429` и `5xx`. `finish_reason` различает `length`, `tool_calls` и `stop`, вместо того чтобы всегда врать `stop`.

**Несколько аккаунтов и переключение по остатку.** Запросы идут по аккаунтам, отсортированным по **пятичасовому окну** квоты — тому, которое заканчивает сессию. Закреплённый аккаунт («pin») получает приоритет, но только пока у него больше 5% пятичасового остатка: на пяти процентах он перестаёт быть первым, и запрос уходит туда, где окно полнее. Это и есть бесшовное переключение — не после `429`, а до него.

**Слой выхода, который переживает смерть своих каналов.** Там, где Гугл заблокирован, мост идёт через smart-DNS релеи: резолвер выдаёт адрес эджа, TCP идёт туда, SNI остаётся гугловым, настоящий сертификат проверяется до конца. Каналы перебираются цепочкой, а сторож раз в две минуты щупает живой канал **настоящим ответом**, а не только рукопожатием: релей умеет принимать TCP вечно и никогда не завершать TLS, и ровно так один канал молча умер на три часа. Два провала — и маршрут уходит на следующий канал, который прошёл ту же пробу.

## Режимы выхода

Переключатель в панели меняет то, как трафик покидает машину:

| Режим | Что делает шим |
| --- | --- |
| `DNS` | идёт в smart-DNS релей из `route` / `routeChain`, SNI и сертификат гугловые |
| `Proxy` | CONNECT в `proxy`, потом в `fallbackProxy` |
| `VPN` | ничего: трафик уже уходит через туннель, шим только проверяет, что он поднят |
| `Direct` | ничего: без релеев вообще |

Режим — явное поле `mode` в `~/.dsh/ag-egress.json`, а не следствие того, какие поля случайно заполнены. Старые конфиги без `mode` читаются по тем же полям, что и раньше.

<details>
<summary><b>Правила, которые меняют поведение</b></summary>

- **`direct` сторожем не продвигается никогда.** Это не релей, а его отсутствие: поставить его в голову цепочки значит молча выключить релеи.
- **Провал пробы — это не только провал TCP.** Если после рукопожатия пришёл ответ с текстом про регион, канал считается мёртвым: транспорт жив, маршрут бесполезен.
- **Одна проба обслуживает всех.** Сторож, `/bench` и `/watchdog` делят один замер 30 секунд (`AG_PROBE_TTL_MS`), вместо того чтобы платить трижды.
- **Мёртвая первая нога не тормозит запросы.** Канал, упавший в последние две минуты (`AG_FAILURE_MEMORY_MS`), уезжает за живые в порядке перебора — ещё до блика сторожа.
- **Смена сети сбрасывает кэши.** Появился или исчез внешний IPv4 — все замеры были про другую сеть.

Поле прокси принимает `host:port`, `http://логин:пароль@host:port`, `socks5://host:port` и `socks5h://` (удалённый DNS). Чужая схема вроде `ftp://` отклоняется, а не читается как HTTP: адрес, который «сохранился», но ведёт не туда, хуже честного отказа. Под полем видно, что именно понято, а «проверить» открывает туннель, ничего не записывая.

Панель не опрашивает шим, а слушает: `GET /events` отдаёт тот же документ, что и `GET /`, но потоком, и кадр уходит только при изменении. Простаивающая панель не тратит запросов.

</details>

Детали, скрипты и разбор «какой режим под мою сеть» — [docs/transports.md](docs/transports.md). Про квоты — [docs/quotas.md](docs/quotas.md).

## Картинки

Рисовать умеет любая модель в харнессе — словами, без команд. «Нарисуй кота» уходит в `gemini-3.1-flash-image`, даже если в профиле стоит текстовая модель: мост смотрит на последнее сообщение пользователя и, если там просьба что-то изобразить, сам подставляет нужную модель.

Ответ приходит путём к файлу: картинка ложится в `~/.dsh/images/`, а в текст подставляется `![generated image](путь)`, который DSH рендерит. Если модель промолчала, всё равно будет строка «Generated an image.» — пустой ответ неотличим от сломанного.

Что уходит в рисование: глагол + предмет («нарисуй кота», `draw a fox`), правка готовой картинки (приложи и скажи «перерисуй в акварель»). Что не уходит: «что на этой картинке», «опиши фото» — это чтение, и оно остаётся у обычной модели. Три ручки: `AG_IMAGE_MODEL`, `AG_IMAGE_DIR`, `AG_IMAGE_AUTO=0`. Детали — [docs/images.md](docs/images.md).

```yaml
- insert:
    - id: web-search
      name: "./plugins/web-search/index.js"
```

## Настройка

Всё через переменные окружения; полный список с дефолтами — [`.env.example`](.env.example). Главное:

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `AG_BRIDGE_PORT` | `8787` | Порт с OpenAI-совместимым API |
| `AG_BRIDGE_SECRET` | `local-bridge` | Bearer, который принимает мост |
| `AG_EGRESS` | `1` | `0` полностью выключает шим |
| `AG_EGRESS_PORT` | `8789` | Порт CONNECT-шима |
| `AG_EGRESS_FILE` | `~/.dsh/ag-egress.json` | Конфиг маршрутизации; дефолты зашиты |
| `AG_EGRESS_DNS_TTL` | `60000` | Кэш ответов резолвера |
| `AG_EGRESS_BUDGET` | `6000` | Бюджет одного CONNECT на все каналы |
| `AG_WATCHDOG_MS` | `120000` | Интервал сторожа |
| `AG_PROBE_TTL_MS` | `30000` | Сколько живёт один замер канала |
| `AG_EXHAUSTED_AT` | `0.05` | Порог, на котором пин перестаёт быть первым |
| `AG_PACE_MS` | `30` | Такт выдачи текста; `AG_PACE=0` выключает |
| `AG_IMAGE_MODEL` | `gemini-3.1-flash-image` | Какая модель рисует картинки |
| `AG_UPSTREAM_TIMEOUT_MS` | `150000` | Сколько апстрим может молчать до первого байта |
| `AG_RESUME_ATTEMPTS` | `2` | Сколько раз оборванный на полуслове ответ продолжается |
| `AG_HUB_VERSION` | `2.26.0` | Версия identity `hub`, ниже которой Гугл не отдаёт часть групп квоты |
| `AG_CLIENT_ID` / `AG_CLIENT_SECRET` | — | OAuth-клиент для обновления токенов |

## Тесты

```bash
cd bridge
npm test            # юнит + egress + режимы + интеграционные
npm run smoke       # четыре запроса (модели, текст, инструменты, стрим); нужен запущенный мост
```

Юнит- и интеграционные наборы самодостаточны: поднимают мок Cloud Code, поэтому упавший тест означает код, а не сеть. С egress иначе — он открывает настоящие TLS-соединения, чтобы проверить, что `probeChannel` отличает живой канал от мёртвого; для него нужна исходящая сеть, в изолированном CI он не пройдёт.

Предпросмотр панели для документации: `node preview/build-preview.mjs dns|proxy` собирает HTML из настоящего CSS панели.

## Честные ограничения

- **Неофициальный транспорт.** Cloud Code — не публичный API; Гугл меняет его без предупреждения, и однажды мосту понадобится патч. Твой аккаунт, твой риск, твоя подписка.
- **Скорость ограничена моделью.** Замеры на сыром потоке: `gemini-3.8-flash` — 85–140 токенов/с (у `-tiered` стабильно выше, ~140), `gemini-3-flash` — ~230. Маршрут не влияет: четыре канала и direct дают одно и то же число. Счётчики в клиентах вроде DSH могут показывать больше — они считают и токены размышлений, и JSON вызовов инструментов.
- **`gemini-3.8-flash` на части тарифов существует только как `-tiered`**; алиас разрешает это сам.
- **Размышления приходят двумя большими блоками**, поэтому сгладить их нельзя, не задержав ответ. Текст плавный, thinking — кусками.
- **Релеи — чужая инфраструктура.** Они видят SNI и объём, но не содержимое TLS. И умирают без предупреждения.
- **Инструменты заточены под Windows**: `start.cmd` и `install-autostart.ps1` — Windows, `start.sh` покрывает macOS/Linux, но автозапуск — нет.
